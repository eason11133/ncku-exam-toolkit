## 環境與工具（20 個）

### Docker（Docker）
分類：Demo 涵蓋｜常見說法：容器工具、Docker 平台
**它是什麼？** 把程式和需要的軟體包在一個隔離環境裡，讓不同電腦比較容易跑出相同的結果。Docker 自己不是作業系統，它仍使用主機的核心。
**舉個例子：** 考前 Demo 把 ROS 2、gcc、make 放在同一個 Docker 環境。
**什麼時候會用到？** 你的電腦缺少 ROS 2 或版本不合時，先使用指定容器。
**現有觀念文章：** `ncku-docker-debug`

### 映像檔（Docker image）
分類：Demo 涵蓋｜常見說法：image、映像、映像檔案
**它是什麼？** 可以拿來建立容器的環境範本，內含程式、套件和設定。它不是正在執行的程式。
**舉個例子：** 先 docker build 產生 image，再由 image 啟動 container。
**什麼時候會用到？** 需要複製同樣的練習環境時。
**現有觀念文章：** `ncku-docker-debug`

### 容器（Container）
分類：Demo 涵蓋｜常見說法：docker container、容器實例
**它是什麼？** 用映像檔啟動後的實際執行環境。裡面的檔案或程式可以跟主機有所區隔。
**舉個例子：** 執行 docker run 後進入一個容器，另開終端機可 docker exec 進同一個。
**什麼時候會用到？** 確認不同視窗是否真的在同一環境裡。
**現有觀念文章：** `ncku-docker-debug`

### Dockerfile（Dockerfile）
分類：Demo 涵蓋｜常見說法：容器建置檔
**它是什麼？** 告訴 Docker 要從哪個基礎映像開始、安裝什麼、放哪些檔案的指令清單。
**舉個例子：** Demo 用 Dockerfile 建立已安裝 ROS 2 的 image。
**什麼時候會用到？** 要重建環境或查看裡面有哪些套件時。
**現有觀念文章：** `ncku-docker-debug`

### 建置映像（docker build）
分類：Demo 涵蓋｜常見說法：建置 image、build image
**它是什麼？** 讀 Dockerfile 並產生新的映像檔。建置時可能會下載套件，所以第一次通常需要網路。
**舉個例子：** docker build -t srecruit-demo demo/。
**什麼時候會用到？** 練習環境尚未建立，或 Dockerfile 更新後。
**現有觀念文章：** `ncku-docker-debug`

### 啟動容器（docker run）
分類：Demo 涵蓋｜常見說法：run container、執行容器
**它是什麼？** 用指定 image 建立並啟動一個容器。常見選項會控制互動、名稱及結束後是否移除。
**舉個例子：** docker run --rm -it --name srecruit-demo srecruit-demo。
**什麼時候會用到？** 要開始執行 Demo 裡的程式時。
**現有觀念文章：** `ncku-docker-debug`

### 進入已運作容器（docker exec）
分類：Demo 涵蓋｜常見說法：exec、第二個 shell
**它是什麼？** 在同一個正在執行的容器內再開一個程式或 shell，不是建立另一個獨立環境。
**舉個例子：** docker exec -it srecruit-demo bash。
**什麼時候會用到？** ROS 2 需要同時開 publisher、processor 和 CLI。
**現有觀念文章：** `ncku-docker-debug`

### 結束自動移除（--rm）
分類：Demo 涵蓋｜常見說法：rm、容器清除
**它是什麼？** docker run 的 --rm 表示容器停止時自動刪掉容器本體，不等於刪除 image。沒有另外保存的容器內修改可能跟著消失。
**舉個例子：** 想保留修改過的檔案，可以改用 bind mount。
**什麼時候會用到？** 擔心練習成果在容器結束後不見時。
**現有觀念文章：** `ncku-docker-debug`

### 終端機（Terminal）
分類：Demo 涵蓋｜常見說法：命令列視窗、終端
**它是什麼？** 讓你輸入指令、看到程式輸出的介面。程式佔住一個終端機時，可以開第二個來觀察它。
**舉個例子：** 終端機 A 跑 publisher，B 跑 processor，C 執行 ros2 topic echo。
**什麼時候會用到？** 要同時操作多個長時間執行的程式時。
**現有觀念文章：** `ncku-docker-debug`

### 命令殼層（Shell）
分類：Demo 涵蓋｜常見說法：bash、命令解譯器
**它是什麼？** 接收你輸入的指令，並呼叫程式執行的環境。Bash 是常見的一種 shell。
**舉個例子：** 在 shell 輸入 cd section2-1 進入指定資料夾。
**什麼時候會用到？** 複製指令後不知道應該貼在哪裡時。
**現有觀念文章：** `ncku-docker-debug`

### 命令列介面（Command-Line Interface）
分類：Demo 涵蓋｜常見說法：CLI、指令介面
**它是什麼？** 不透過圖形按鈕，而是用文字指令操作程式的方式。
**舉個例子：** ros2 node list 是 ROS 2 CLI 指令。
**什麼時候會用到？** 考場需要觀察執行狀態或快速重現測試時。
**現有觀念文章：** `ncku-docker-debug`

### 工作目錄（Working directory）
分類：Demo 涵蓋｜常見說法：當前目錄、cwd
**它是什麼？** 你目前所在的資料夾，會影響相對路徑指向哪裡。
**舉個例子：** cd section2-1 後才執行 python3 publisher.py。
**什麼時候會用到？** 遇到檔案找不到、make 找不到目標時。
**現有觀念文章：** `ncku-docker-debug`

### Windows Linux 子系統（Windows Subsystem for Linux）
分類：Demo 涵蓋｜常見說法：WSL、WSL2
**它是什麼？** 讓 Windows 上能使用 Linux 使用者空間與工具的功能；Docker Desktop 的 Windows 練習常搭配它。
**舉個例子：** Windows 使用者可在 WSL 終端機操作 Docker。
**什麼時候會用到？** 需要 Linux 指令或 POSIX 編譯環境時。
**現有觀念文章：** `ncku-docker-debug`

### 編譯器（Compiler）
分類：Demo 涵蓋｜常見說法：clang、cc、編譯
**它是什麼？** 把 C 等原始碼翻譯成可以執行的機器程式；程式碼不符合語法會出錯。
**舉個例子：** cc demo_asm.c -o demo_asm。
**什麼時候會用到？** 拿到 C 原始碼，要先編譯再執行時。
**現有觀念文章：** `ncku-docker-debug`

### GCC 編譯器（GNU Compiler Collection）
分類：Demo 涵蓋｜常見說法：gcc、GNU C compiler
**它是什麼？** 常見的 C/C++ 編譯器工具集。官方 Demo 的 pthread 程式可以用 gcc 編譯。
**舉個例子：** gcc -pthread main.c -o main。
**什麼時候會用到？** 遇到編譯旗標或 pthread 連結問題時。
**現有觀念文章：** `ncku-docker-debug`

### Make 建置工具（make）
分類：Demo 涵蓋｜常見說法：Makefile、建置指令
**它是什麼？** 依 Makefile 中定義的規則執行編譯或其他命令，省去每次手打長指令。
**舉個例子：** make run 會依 Demo 的規則編譯並執行範例。
**什麼時候會用到？** 需要重現指定的測試步驟時。
**現有觀念文章：** `ncku-docker-debug`

### 建置目標（Make target）
分類：Demo 涵蓋｜常見說法：target、make clean、make mistake
**它是什麼？** Makefile 中一個有名字的工作，可能是編譯、測試、清除檔案，不一定會建立實體檔。
**舉個例子：** make mistake 執行傳輸數量設定錯誤的示範。
**什麼時候會用到？** 要分別跑 critical section 或 transfer engine 時。
**現有觀念文章：** `ncku-docker-debug`

### 原始碼（Source code）
分類：Demo 涵蓋｜常見說法：source、程式碼
**它是什麼？** 人寫的文字程式，通常要先由 Python 直譯器執行，或由 C 編譯器產生可執行檔。
**舉個例子：** publisher.py 是 Python 原始碼；demo_asm.c 是 C 原始碼。
**什麼時候會用到？** 辨別要用 python3、cc 還是 make 執行時。
**現有觀念文章：** `ncku-docker-debug`

### 行程（Process）
分類：Demo 涵蓋｜常見說法：程序、進程
**它是什麼？** 一個正在執行的程式實例，有自己的位址空間與作業系統資源。跟同程式內的多條執行緒不同。
**舉個例子：** publisher.py 和 processor.py 分別啟動後是不同 process。
**什麼時候會用到？** 判斷錯誤是否發生在不同程式之間時。
**現有觀念文章：** `ncku-docker-debug`

### 標準輸出（Standard output）
分類：Demo 涵蓋｜常見說法：stdout、輸出結果
**它是什麼？** 程式平常印出文字的管道，終端機通常會顯示它。
**舉個例子：** printf 或 print 的內容出現在執行視窗。
**什麼時候會用到？** 要看實際訊息、測試輸出與排查結果時。
**現有觀念文章：** `ncku-docker-debug`

## ROS 2 通訊（28 個）

### ROS 2（Robot Operating System 2）
分類：Demo 涵蓋｜常見說法：機器人作業系統2、ROS2
**它是什麼？** 讓多個程式彼此交換資料、協作的機器人軟體框架。雖然名字有 Operating System，它不是取代 Linux 的作業系統。
**舉個例子：** 一個 node 產生數字，另一個 node 收到後處理。
**什麼時候會用到？** 看到 ros2、rclpy、node、topic 等程式時。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`
**接著看：** 節點、主題通道、發布者、訂閱者

### 節點（ROS 2 Node）
分類：Demo 涵蓋｜常見說法：node、ROS 節點
**它是什麼？** ROS 2 裡執行一部分功能並參與通訊的單位。多個 node 可以分開啟動，也可以放在同一 process。
**舉個例子：** publisher node 負責產生數字，processor node 負責加工。
**什麼時候會用到？** 用 ros2 node list 確認程式是否啟動。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`

### 主題通道（ROS 2 Topic）
分類：Demo 涵蓋｜常見說法：topic、話題、資料主題
**它是什麼？** 給有相同主題名稱和相容型別的節點傳遞訊息的通道。可以想成廣播頻道，不需要每位接收者都直接呼叫發送者。
**舉個例子：** publisher 對 /number 發布，processor 訂閱 /number。
**什麼時候會用到？** 發布者正常但訂閱端沒有資料時。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`
**接著看：** 訊息、發布者、訂閱者、服務品質設定

### 發布者（Publisher）
分類：Demo 涵蓋｜常見說法：發佈者、發送端、publish、出版者
**它是什麼？** 負責把訊息送到某個 topic 的物件或節點角色。它不負責等待每位訂閱者逐一答覆。
**舉個例子：** publisher.py 定時發布數字。
**什麼時候會用到？** 查 ros2 node info 的 Publishers 或用 ros2 topic pub 測試時。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`

### 訂閱者（Subscriber）
分類：Demo 涵蓋｜常見說法：訂閱端、訂閱器、subscription、subscribe
**它是什麼？** 訂閱 topic 的接收者，資料到達後可交給 callback 處理。
**舉個例子：** processor 讀 /number 的資料。
**什麼時候會用到？** 訂閱者沒反應，需檢查型別和 topic 名稱時。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`

### 訊息（ROS 2 Message）
分類：Demo 涵蓋｜常見說法：message、msg、訊息資料
**它是什麼？** 一筆在 topic 上傳的資料，會有指定的訊息型別和欄位。它不是任意文字，而是按介面定義的結構。
**舉個例子：** std_msgs/msg/Int32 包含名為 data 的整數欄位。
**什麼時候會用到？** CLI 發送資料格式不對或 callback 讀錯欄位時。
**現有觀念文章：** `ncku-ros2-cli-workflow`
**對應優化方案：** `ros2-topic-pipeline::check-cli`

### 訊息型別（Message type）

**它是什麼？** 描述訊息有哪些欄位、每個欄位用什麼型別。發布與訂閱雙方需要相容。
**舉個例子：** std_msgs/msg/Int32 不是 std_msgs/msg/String。

### 直接記憶體存取（Direct Memory Access）
分類：相關延伸｜常見說法：DMA、直接存取記憶體、直接內存訪問
**它是什麼？** 讓硬體搬運控制器按照設定從記憶體或周邊讀資料，再寫到另一處。CPU 只需設定工作、啟動並處理完成，不用自己逐筆複製。
**舉個例子：** CPU 設好來源、目的地和筆數，DMA 把資料送進 PIO TX FIFO。
**什麼時候會用到？** CPU 長時間忙著把大量資料餵給周邊時。
**現有觀念文章：** `ncku-transfer-engine`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`
**接著看：** PIO 搭配 DMA、DMA 請求訊號、DMA 通道設定、DMA 完成通知、DMA 與執行緒差異

### DMA 控制器（DMA controller）
分類：相關延伸｜常見說法：DMA 硬體、DMA 引擎
**它是什麼？** 真正負責執行 DMA 搬運的硬體元件，可包含多個通道。Demo 的 transfer engine 是執行緒模擬，並不是這個硬體控制器。
**舉個例子：** RP2350 SDK 的 hardware_dma API 控制硬體 DMA。
**什麼時候會用到？** 要把 Demo 概念改寫成 Pico SDK 實際程式時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### PIO 搭配 DMA（PIO with DMA）
分類：相關延伸｜常見說法：PIO+DMA、PIO FIFO DMA、PIO DMA
**它是什麼？** 由 DMA 根據 PIO FIFO 的需求送資料或取資料，減少 CPU 每筆呼叫 blocking API 的工作。仍然要設定資料寬度、來源和目的地位址以及結束條件。
**舉個例子：** DMA 從 uint32_t 陣列送 1000 個 word 到 PIO TX FIFO。
**什麼時候會用到？** CPU 不斷執行 pio_sm_put_blocking 的傳輸迴圈時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`
**接著看：** 直接記憶體存取、可程式化輸入輸出、PIO 資料佇列、DMA 請求訊號、DMA 通道設定

### DMA 請求訊號（DMA Request）
分類：相關延伸｜常見說法：DREQ、DMA pacing、請求訊號
**它是什麼？** 周邊告訴 DMA 現在適合傳送下一筆資料的節奏訊號。它讓 DMA 不會無視 FIFO 空間而瘋狂寫入。
**舉個例子：** 用 pio_get_dreq(pio, sm, true) 取得對應 PIO TX FIFO 的 DREQ。
**什麼時候會用到？** DMA 已啟動但資料速率要跟 PIO 配合時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`
**接著看：** 直接記憶體存取、PIO 搭配 DMA、查詢 PIO DREQ

### 查詢 PIO DREQ（pio_get_dreq）
分類：相關延伸｜常見說法：pio_get_dreq()、取得 DREQ
**它是什麼？** Pico SDK 用來取得指定 PIO、state machine、TX/RX 方向的 DMA 節奏來源。第三個參數 true 表示 TX，false 表示 RX。
**舉個例子：** pio_get_dreq(pio, sm, true)。
**什麼時候會用到？** 設定 channel_config_set_dreq 時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### 阻塞式送入 PIO（pio_sm_put_blocking）
分類：相關延伸｜常見說法：pio_sm_put_blocking()、阻塞寫入 FIFO
**它是什麼？** 把一個 32-bit word 寫進指定 state machine 的 TX FIFO。如果 FIFO 已滿，CPU 會等到可寫。
**舉個例子：** for 迴圈裡一筆筆呼叫此函式，可能讓 CPU 花時間等待。
**什麼時候會用到？** 要解釋為何資料正常但 CPU 無法做其他工作時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### 阻塞等待（Blocking）
分類：相關延伸｜常見說法：阻塞、同步卡住、blocking call
**它是什麼？** 呼叫者必須等某個條件達成，才繼續執行後面的程式。阻塞不一定是錯誤，有時是正確地等資料。
**舉個例子：** pio_sm_put_blocking 在 TX FIFO 滿時等待。
**什麼時候會用到？** 程式停住但 CPU 也許正在等外部裝置時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::fifo-paced-transfer`

### 非阻塞（Non-blocking）
分類：相關延伸｜常見說法：nonblocking、非阻塞式
**它是什麼？** 呼叫後不一定等工作完成才返回，通常需要另查狀態或處理回呼。不是不用檢查錯誤，也不表示一定較快。
**舉個例子：** DMA 啟動後 main 先算別的事情，完成時再讀結果。
**什麼時候會用到？** 要避免 CPU 一直等周邊傳輸時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### DMA 通道設定（DMA channel configuration）
分類：相關延伸｜常見說法：channel_config、dma config、DMA 配置
**它是什麼？** 指定一個 DMA 工作要怎麼搬資料，例如資料寬度、位址增量、DREQ 和完成方式。
**舉個例子：** 讀位址每筆加 4 bytes，寫位址維持在 PIO FIFO 暫存器。
**什麼時候會用到？** 要把 CPU 逐筆送資料的程式改成 DMA 時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-engine-configuration::count-unit`

### DMA 讀取位址遞增（DMA read increment）
分類：相關延伸｜常見說法：read_increment、DMA來源遞增
**它是什麼？** 每搬完一筆，從來源的下一個元素讀資料。要串流送陣列時通常開啟。
**舉個例子：** 陣列 data[0]、data[1]、data[2] 依序送出。
**什麼時候會用到？** DMA 反覆讀到同一個數值時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-engine-configuration::copy-vs-fill`

### DMA 寫入位址遞增（DMA write increment）
分類：相關延伸｜常見說法：write_increment、DMA目的遞增
**它是什麼？** 每搬完一筆是否把寫入位址向後移。往 PIO TX FIFO 寫時，通常不遞增，因為每筆都寫同一個硬體寄存器位置。
**舉個例子：** write_increment=false，目的地是 pio->txf[sm]。
**什麼時候會用到？** 改 DMA 時發現寫入位址不應是陣列時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-engine-configuration::copy-vs-fill`

### DMA 傳輸寬度（DMA transfer width）
分類：相關延伸｜常見說法：DMA_SIZE_32、transfer width、搬運寬度
**它是什麼？** 每次 DMA 讀寫多少 bit 或 byte，要與周邊寄存器寬度與 buffer 排列相符。
**舉個例子：** 32-bit word 常選 DMA_SIZE_32。
**什麼時候會用到？** 結果位元錯位、搬錯筆數時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-engine-configuration::count-unit`

### DMA 完成通知（DMA completion）
分類：相關延伸｜常見說法：transfer complete、DMA 完成、中斷通知
**它是什麼？** DMA 開始不等於資料可立刻用。需要用忙碌狀態、等待函式或中斷確認這筆搬運完成。
**舉個例子：** 啟動後先做其他事，DMA 完成才重用來源 buffer。
**什麼時候會用到？** 傳出去的資料偶爾變亂、buffer 被提早覆寫時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-engine-configuration::overlap-cpu`

### DMA 與快取一致性（DMA cache coherency）
分類：相關延伸｜常見說法：cache coherency、cache flush、快取一致性
**它是什麼？** CPU 和 DMA 可能看到記憶體的不同暫存版本，某些平台需要清理或失效快取。要依硬體快取架構決定，不能對每個 MCU 都假定同樣問題。
**舉個例子：** CPU 修改 buffer 後，先確認 DMA 會讀到最新內容。
**什麼時候會用到？** DMA 傳輸內容像是舊資料，但原始 buffer 已更新時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `dma-cache-coherency::option-1-method`
**接著看：** 直接記憶體存取、快取記憶體、DMA 完成通知

### 雙緩衝（Double buffering）
分類：相關延伸｜常見說法：double buffer、ping pong buffer、雙 buffer
**它是什麼？** 準備兩塊 buffer，這一塊被硬體傳輸時，CPU 處理另一塊。交換前必須確認每塊資料真的完成。
**舉個例子：** DMA 送 A 時，CPU 填 B；下一輪互換。
**什麼時候會用到？** 傳輸與計算可以重疊時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `resource-queues::double-buffer`

### 環形緩衝區（Ring buffer）
分類：相關延伸｜常見說法：circular buffer、環狀佇列、循環緩衝
**它是什麼？** 固定大小陣列配合讀寫位置循環使用，避免資料一多就一直重新配置記憶體。容量滿時要有清楚處理策略。
**舉個例子：** head 指向下次讀，tail 指向下次寫。
**什麼時候會用到？** 連續接收感測器資料或串流封包時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `resource-queues::bounded-queue`

### 背壓（Backpressure）
分類：相關延伸｜常見說法：背壓控制、流量回壓
**它是什麼？** 下游處理不過來時，讓上游減速或暫停，避免無限堆積。FIFO 滿或 queue 滿可能是背壓的一種表現。
**舉個例子：** PIO TX FIFO 滿，CPU 不能再無限制寫入。
**什麼時候會用到？** 資料來源比處理速度快時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `resource-queues::bounded-queue`

### 吞吐量（Throughput）
分類：相關延伸｜常見說法：資料吞吐、有效吞吐、每秒筆數
**它是什麼？** 一秒內真正處理或搬運完成的資料量；不等於單筆資料要等多久。
**舉個例子：** 一秒成功送出 10 萬個 word。
**什麼時候會用到？** 比較 CPU 迴圈與 DMA 的總傳輸能力時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `benchmark-correctness::compare-tradeoff`

### 延遲（Latency）
分類：相關延伸｜常見說法：反應時間、單筆延遲
**它是什麼？** 從開始要求到完成回應的一段時間。吞吐量變高，不表示每筆延遲一定下降。
**舉個例子：** 一次 DMA 啟動加等待，可能比送單一 word 還花時間。
**什麼時候會用到？** 題目要改善反應速度時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `perf-tail-latency::option-1-method`

### 時脈除頻（Clock divider）
分類：相關延伸｜常見說法：clkdiv、PIO clock divider、時鐘分頻
**它是什麼？** 讓 PIO state machine 的指令執行速度相對於系統時鐘變慢。速度越高也必須確保外部裝置能跟上。
**舉個例子：** 調整 PIO 的 clock divider 會改變訊號時間間隔。
**什麼時候會用到？** 資料送出時序不正確時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `pio-delay-clock::option-2-state-machine-clock-divider`

### PIO 停滯（PIO stall）
分類：相關延伸｜常見說法：stall、state machine stalled、PIO卡住
**它是什麼？** PIO 因等待資料、等待 FIFO 空間或其他條件而暫停推進。不是所有停滯都代表程式錯。
**舉個例子：** pull block 遇到 TX FIFO 空，會等下一筆資料。
**什麼時候會用到？** PIO 動作突然停住時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `pio-fifo-stall::option-1-tx-fifo`

### 中斷請求（Interrupt Request）
分類：相關延伸｜常見說法：IRQ、interrupt、中斷
**它是什麼？** 硬體透過中斷通知 CPU 有事件需要處理，CPU 可以先做其他事，而不必每次都反覆詢問狀態。
**舉個例子：** DMA 工作完成後觸發 IRQ。
**什麼時候會用到？** 不想用 while 不停檢查 transfer_busy 時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `transfer-interrupt-or-poll::option-1-method`

### 輪詢（Polling）
分類：相關延伸｜常見說法：poll、輪詢檢查
**它是什麼？** CPU 主動一次又一次詢問硬體是否完成，簡單但如果空轉可能很耗 CPU。
**舉個例子：** while (dma_channel_is_busy(ch)) 不停查。
**什麼時候會用到？** 決定用 busy loop、sleep 還是中斷通知時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### 周邊裝置（Peripheral）
分類：相關延伸｜常見說法：外設、外圍裝置
**它是什麼？** CPU 外部或晶片內部提供特定功能的硬體單元，例如 PIO、UART、SPI、ADC。周邊常有自己的寄存器與 FIFO。
**舉個例子：** PIO 的 TX FIFO 是 DMA 寫入的周邊端。
**什麼時候會用到？** 設定 DMA 來源或目的地時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### 暫存器（Register）
分類：相關延伸｜常見說法：硬體暫存器、寄存器
**它是什麼？** 硬體裡用來保存狀態或設定的固定位置。CPU 暫存器與硬體周邊暫存器用途不同，要看上下文。
**舉個例子：** PIO 的 TX FIFO 有對應的寫入介面與硬體位址。
**什麼時候會用到？** 閱讀 pio->txf[sm] 或位元旗標時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

### 記憶體對映 I/O（Memory-Mapped I/O）
分類：相關延伸｜常見說法：MMIO、記憶體映射 IO
**它是什麼？** 把周邊控制暫存器放在 CPU 可用位址操作的位置；同樣的 C 指標讀寫，在這裡可能是在操作硬體。
**舉個例子：** 對 PIO TX 寄存器地址寫入，資料送進 FIFO。
**什麼時候會用到？** 不懂為什麼 DMA 目的地不是一般 RAM 陣列時。
**現有觀念文章：** `ncku-pio-dataflow`
**對應優化方案：** `rp2350-pio-fifo::pio-with-dma`

## ROS 2 延伸（22 個）

### 執行器（ROS 2 Executor）
分類：相關延伸｜常見說法：Executor、執行器、事件執行器
**它是什麼？** 負責安排哪些已準備好的 ROS 2 callback 可以執行。它決定工作何時開始，不會自動讓每段 callback 變快。
**舉個例子：** A callback 阻塞時，單執行緒 executor 的 B 可能要排隊。
**什麼時候會用到？** callback 明明準時收到事件卻晚開始時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `single-threaded-executor::shorten-callback`

### 單執行緒執行器（SingleThreadedExecutor）
分類：相關延伸｜常見說法：單執行緒 Executor、single threaded executor
**它是什麼？** 同一時間由一條執行緒執行 callback。簡單但一個耗時 callback 可能拖延其他 callback。
**舉個例子：** A 卡住 300ms，B 就可能得等 A 結束。
**什麼時候會用到？** ROS 2 timer 延遲且 callback 有耗時 I/O 時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `single-threaded-executor::shorten-callback`

### 多執行緒執行器（MultiThreadedExecutor）
分類：相關延伸｜常見說法：多執行緒 Executor、multi threaded executor
**它是什麼？** 用多條工作執行緒安排可並行的 callback，但能否重疊執行還受 callback group 限制。
**舉個例子：** 分開群組的兩個 callback 可以在符合條件時重疊。
**什麼時候會用到？** 兩個獨立 callback 互相等待時。
**現有觀念文章：** `ros2-ste-multithreaded-groups`
**對應優化方案：** `single-threaded-executor::multithreaded-callback-groups`

### 回呼群組（Callback Group）
分類：相關延伸｜常見說法：Callback Group、回調組
**它是什麼？** ROS 2 用來決定同組 callback 能否重疊執行的設定。多執行緒 executor 不代表預設互斥群組會自動並行。
**舉個例子：** A、B 分別放進不同互斥群組。
**什麼時候會用到？** 改 MultiThreadedExecutor 後仍完全不並行時。
**現有觀念文章：** `ros2-ste-multithreaded-groups`
**對應優化方案：** `single-threaded-executor::multithreaded-callback-groups`
**接著看：** 執行器、多執行緒執行器、互斥回呼群組、可重入回呼群組

### 互斥回呼群組（MutuallyExclusiveCallbackGroup）
分類：相關延伸｜常見說法：互斥 Callback Group
**它是什麼？** 同一群組內一次只讓一個 callback 執行，即使 executor 有多條 thread。兩個不同群組仍可能重疊。
**舉個例子：** A、B 若共用同一群組，就不能同時跑。
**什麼時候會用到？** 想避開共享狀態競爭時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `single-threaded-executor::multithreaded-callback-groups`

### 可重入回呼群組（ReentrantCallbackGroup）
分類：相關延伸｜常見說法：Reentrant、可重入群組
**它是什麼？** 允許同一群組的 callback 重疊，甚至同一個 callback 的多個呼叫可能重疊。必須確認程式真的能安全重入。
**舉個例子：** 處理 I/O 的兩次 callback 可以重疊，但 shared list 要同步。
**什麼時候會用到？** 需要並行又已處理共享資料安全時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `single-threaded-executor::multithreaded-callback-groups`

### 服務品質設定（Quality of Service）
分類：相關延伸｜常見說法：QoS、QoS profile、傳輸服務品質
**它是什麼？** ROS 2 用來控制訊息保存、可靠性等行為的一組設定。發布端與訂閱端的 QoS 不相容時可能收不到資料。
**舉個例子：** 感測器採 Best Effort，訂閱者要求 Reliable 可能不相容。
**什麼時候會用到？** topic 名稱與型別正確卻仍無訊息時。
**現有觀念文章：** `ncku-ros2-qos`
**對應優化方案：** `ros2-qos-profile::fix-compatibility`

### 傳輸可靠性（Reliability policy）
分類：相關延伸｜常見說法：Reliable、Best Effort、可靠性政策
**它是什麼？** 決定通訊偏向確保資料送達，還是容忍部分遺失以維持效率；具體行為還受 DDS 和網路影響。
**舉個例子：** 不要求每張影像都完整時可能使用 Best Effort。
**什麼時候會用到？** 網路擁塞、影像與感測器串流時。
**現有觀念文章：** `ncku-ros2-qos`
**對應優化方案：** `ros2-qos-profile::reliability-choice`

### 訊息佇列深度（QoS History depth）
分類：相關延伸｜常見說法：depth、Keep Last、歷史深度
**它是什麼？** 指定最多保存多少筆尚待處理的訊息。深度大可能增加記憶體和資料變舊風險。
**舉個例子：** 每秒進 100 筆只處理 10 筆時，佇列很快堆滿。
**什麼時候會用到？** 訂閱 callback 一直落後時。
**現有觀念文章：** `ncku-ros2-qos`
**對應優化方案：** `ros2-qos-profile::keep-last-depth`

### 名稱重映射（ROS 2 remapping）
分類：相關延伸｜常見說法：remap、topic remap、重新映射
**它是什麼？** 啟動程式時把它使用的 topic 或 node 名稱改成另一個，不必直接修改程式原始碼。
**舉個例子：** 將 /input 映射成 /number，讓既有 node 接上資料。

### ROS 網域識別（ROS_DOMAIN_ID）

**它是什麼？** 把同一網路上的 ROS 2 系統分群的一個設定。不同 domain 的 node 通常不會互相發現。
**舉個例子：** 兩個終端機 ROS_DOMAIN_ID 不同，node list 可能找不到對方。

### ROS 命名空間（ROS namespace）
分類：相關延伸｜常見說法：namespace、命名空間
**它是什麼？** 讓同名 node 或 topic 在不同層級下分開管理，常用於多台機器人。
**舉個例子：** /robot1/number 和 /robot2/number 是不同主題。

### ROS 參數（ROS 2 Parameter）

**它是什麼？** 讓 node 在執行時保存與讀取設定值。改變參數後是否會立即影響程式，取決於實作。
**舉個例子：** 把發布頻率或閾值放成 ROS parameter。

**它是什麼？** 把程式裡的資料結構轉成可傳輸或儲存的位元組表示。需要跟接收端約定格式。
**舉個例子：** 將 ROS 2 訊息欄位編碼後跨程序傳送。

### 訊息堆積（Message backlog）
分類：相關延伸｜常見說法：topic backlog、排隊訊息、處理落後
**它是什麼？** 生產資料的速度高於消費速度，未處理訊息越積越多。只加大 queue 不會讓處理速度變快。
**舉個例子：** 每秒收到 1000 筆，callback 只處理 300 筆。

### 服務客戶端（ROS 2 Service client）
分類：相關延伸｜常見說法：client、service request、服務請求方
**它是什麼？** 主動向服務端送出一筆 request 並等待或非同步接收 response 的角色。
**舉個例子：** client.call_async(request)。

### 服務端（ROS 2 Service server）
分類：相關延伸｜常見說法：server、服務提供者
**它是什麼？** 接到 Service request 後執行工作並提供 response。跟一直廣播的 publisher 不同。
**舉個例子：** 服務端收到設定查詢後回傳值。
**什麼時候會用到？** client 沒回應，要確認 server 是否存在時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `ros2-service-client-deadlock::option-1-call-async`

### 非同步服務呼叫（call_async）
分類：相關延伸｜常見說法：async service、非同步請求
**它是什麼？** 發出請求先取得一個代表未來結果的物件，之後完成時再處理；不需在同一 callback 裡同步等結果。
**舉個例子：** 在 timer callback 呼叫 client.call_async。
**什麼時候會用到？** 同步 call 在 callback 裡造成死鎖風險時。
**現有觀念文章：** `ncku-ros2-executor`

### 未來結果物件（Future）
分類：相關延伸｜常見說法：future result、非同步結果
**它是什麼？** 代表稍後才會完成的工作結果，可能成功、失敗或取消。不是立即取得的普通值。
**舉個例子：** future.add_done_callback 設定結果到達後要做什麼。
**什麼時候會用到？** 要追蹤非同步服務請求是否完成時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `ros2-service-client-deadlock::option-1-call-async`

### ROS 2 回呼死鎖（ROS 2 callback deadlock）
分類：相關延伸｜常見說法：service deadlock、callback deadlock、服務死鎖
**它是什麼？** 某 callback 同步等待另一個也必須由 executor 執行的工作，但排程條件讓那個工作永遠無法開始。
**舉個例子：** 在同一個互斥群組中同步等待 Service response。
**什麼時候會用到？** Service 有送出卻一直等不到回覆時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `ros2-service-client-deadlock::option-2-callback-groups`

### 發布頻率（Publish rate）
分類：相關延伸｜常見說法：message rate、Hz、每秒發送次數
**它是什麼？** 一秒發布幾筆訊息，跟 subscriber 真正收到的頻率不一定相同。
**舉個例子：** timer 每 0.1 秒發一次，理論大約 10 Hz。
**什麼時候會用到？** 想確認瓶頸在發送端還是接收端時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `ros2-topic-pipeline::check-cli`

### 端到端延遲（End-to-end latency）
分類：相關延伸｜常見說法：E2E latency、全程延遲
**它是什麼？** 從資料產生到最終處理結果可用的整段時間，可能包含排隊、傳輸、callback 和計算。
**舉個例子：** 接收端收到的時間減去發送端附帶的時間戳。
**什麼時候會用到？** 改 executor 後要驗證整體是否真的變快時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `benchmark-correctness::compare-tradeoff`

## 並行與效能延伸（30 個）

### 互斥鎖（Mutex）
分類：相關延伸｜常見說法：mutex、pthread_mutex_t、互斥量
**它是什麼？** 一次只讓一個執行緒進入臨界區的鎖。跟 spinlock 相比，等待時有機會阻塞休眠，適合情況取決於鎖時間和平台。
**舉個例子：** pthread_mutex_lock、pthread_mutex_unlock。
**什麼時候會用到？** 鎖等待時間偏長，CPU 一直忙等時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `spinlock-critical-section::use-mutex`

### 原子操作（Atomic operation）
分類：相關延伸｜常見說法：atomic、_Atomic、原子變數
**它是什麼？** 對共享數值進行不可被其他執行緒看見「做一半」的操作；還需要依需求選擇適當記憶體順序。
**舉個例子：** atomic_fetch_add 可安全累加計數器。
**什麼時候會用到？** 只需安全更新單一計數器，鎖可能過重時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-atomic-counter::option-1-atomic`

### 資料競爭（Data race）
分類：相關延伸｜常見說法：race condition、資料競態、資料競爭
**它是什麼？** 多條執行緒未正確同步就同時存取同一資料，而且至少一個在寫。C 的資料競爭可能造成未定義行為。
**舉個例子：** 兩個 worker 都不加鎖修改 counter。
**什麼時候會用到？** 結果偶爾錯、加了 volatile 也沒用時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `spinlock-critical-section::per-thread-count`

### 條件變數（Condition variable）
分類：相關延伸｜常見說法：pthread_cond_t、condvar、條件通知
**它是什麼？** 當某個共享條件還不成立時，讓執行緒等候通知，避免一直空轉。真正的條件要配合 mutex 保護並用 while 重查。
**舉個例子：** queue 空時等待 not_empty，有資料時 producer 通知。
**什麼時候會用到？** 生產者消費者程式空佇列仍吃滿 CPU 時。
**現有觀念文章：** `ncku-pthread-condvar-queue`
**對應優化方案：** `pthread-condition-queue::condition-predicate-loop`

### 生產者消費者（Producer–consumer）
分類：相關延伸｜常見說法：producer consumer、生產者-消費者模型
**它是什麼？** 一方建立資料或工作，另一方負責處理。若兩邊速度不同，需要佇列與滿載策略。
**舉個例子：** producer 持續加入資料，consumer 持續取出處理。
**什麼時候會用到？** 串流資料、背景工作或多執行緒 queue 時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-condition-queue::bounded-ring-buffer`

### 執行緒池（Thread pool）
分類：相關延伸｜常見說法：worker pool、固定工作執行緒
**它是什麼？** 事先建立少數執行緒，反覆從佇列取工作，而不是每筆任務都新建一條 thread。
**舉個例子：** 固定 4 個 worker 處理很多小任務。
**什麼時候會用到？** pthread_create 的建立成本開始影響效能時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-thread-lifecycle::option-1-worker-pool`

### 死鎖（Deadlock）
分類：相關延伸｜常見說法：死結、鎖死
**它是什麼？** 兩條以上執行緒互相等對方釋放資源，導致都無法繼續。增加執行緒數通常不能解決鎖順序問題。
**舉個例子：** A 先鎖 M1 等 M2，B 先鎖 M2 等 M1。
**什麼時候會用到？** 程式沒有崩潰卻永遠不結束時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-deadlock-order::option-1-method`

### 鎖取得順序（Lock ordering）
分類：相關延伸｜常見說法：lock hierarchy、固定鎖順序
**它是什麼？** 多把鎖都統一按相同順序取得，避免不同執行緒形成循環等待。
**舉個例子：** 所有地方都先 lock A 再 lock B。
**什麼時候會用到？** 程式需要同時持有兩把 mutex 時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-deadlock-order::option-1-method`

### 執行緒安全關閉（Thread shutdown）
分類：相關延伸｜常見說法：worker shutdown、close queue、關閉旗標
**它是什麼？** 停止 producer、通知等待者醒來、處理剩餘工作並 join，讓程式能正常結束。
**舉個例子：** 設定 closed=true，再 pthread_cond_broadcast 喚醒等待者。
**什麼時候會用到？** 程式能執行工作，但關閉時卡住。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `pthread-timeout-shutdown::option-1-broadcast`

### 偽共享（False sharing）
分類：相關延伸｜常見說法：cache line contention、假共享
**它是什麼？** 兩條執行緒雖然更新不同變數，但變數剛好在同一 cache line，造成快取反覆爭用。
**舉個例子：** 兩個 per-thread counter 放得太靠近。
**什麼時候會用到？** 沒有同一把鎖卻因共享 cache line 變慢時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `cpu-memory-locality::avoid-false-sharing`

### 快取記憶體（CPU Cache）
分類：相關延伸｜常見說法：cache、快取、緩存記憶體
**它是什麼？** CPU 附近保存最近或常用資料的高速記憶體，常能讓重複或連續存取更快。它和程式自己寫的 map cache 是不同概念。
**舉個例子：** 走訪連續陣列常比到處追指標更友善。
**什麼時候會用到？** 程式瓶頸是記憶體存取而不是計算時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `cpu-memory-locality::contiguous-storage`

### 快取未命中（Cache miss）
分類：相關延伸｜常見說法：cache miss、快取不命中
**它是什麼？** CPU 想要的資料不在目前快取層級，需要到較慢的層級取回。
**舉個例子：** 對巨大 linked list 跳躍存取可能產生很多 miss。
**什麼時候會用到？** 程式運算很簡單卻跑得比預期慢時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `cpu-memory-locality::contiguous-storage`

### 記憶體局部性（Memory locality）
分類：相關延伸｜常見說法：locality、資料局部性
**它是什麼？** 彼此接近的資料或近期會再用的資料，通常比較容易被快取有效利用。
**舉個例子：** 把要逐一處理的數值放連續陣列。
**什麼時候會用到？** 優化大量陣列或 struct 走訪時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `cpu-memory-locality::contiguous-storage`

### 位元組序（Endianness）
分類：相關延伸｜常見說法：endianness、大小端序、端序
**它是什麼？** 多個 byte 組成整數時，先存高位還是低位的規則。它跟 bit 在 PIO shift register 裡移動的方向不是同一件事。
**舉個例子：** 0x12345678 的 big-endian bytes 是 12 34 56 78。
**什麼時候會用到？** 解析封包或 DMA 收到的資料時。
**現有觀念文章：** `ncku-binary-packet-parsing`
**對應優化方案：** `safe-binary-decoding::shift-or-big-endian`

### 位元組順序（Byte order）
分類：相關延伸｜常見說法：big endian、little endian、位元組排列
**它是什麼？** 描述多 byte 數值在記憶體或傳輸格式中如何排列。必須照協定規格解析。
**舉個例子：** 同四個 bytes 以不同端序讀會得到不同數字。
**什麼時候會用到？** 跨 CPU、網路或硬體搬資料時。
**現有觀念文章：** `ncku-binary-packet-parsing`
**對應優化方案：** `safe-binary-decoding::shift-or-big-endian`

### 封包（Packet）
分類：相關延伸｜常見說法：packet、資料封包
**它是什麼？** 按照某種協定放在一起的一段 bytes，通常包含欄位、長度或其他檢查資料。不是所有 byte 都能直接轉成 C struct。
**舉個例子：** 收到 4 bytes，要按 endian 和長度檢查後解讀。
**什麼時候會用到？** 從 UART、SPI 或網路接資料時。
**現有觀念文章：** `ncku-binary-packet-parsing`
**對應優化方案：** `safe-binary-decoding::shift-or-big-endian`

### 效能剖析（Profiling）
分類：相關延伸｜常見說法：profiler、效能分析、熱點分析
**它是什麼？** 蒐集程式花時間在哪些函式或段落的證據，避免只靠猜想改程式。
**舉個例子：** 先量 callback 解析、計算、發布各花多少時間。
**什麼時候會用到？** 不知道慢在哪段時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `benchmark-correctness::profile-hotspot`

### 基準版本（Baseline）
分類：相關延伸｜常見說法：基線、原始效能、原版本
**它是什麼？** 改程式前先保存能重現的輸出、測試指令和耗時，當作對照。否則很難證明新方法有用。
**舉個例子：** 保存原版的 30 次測量中位數。
**什麼時候會用到？** 要比較優化前後而不想靠感覺時。
**現有觀念文章：** `ncku-performance-benchmark`
**對應優化方案：** `benchmark-correctness::baseline`

### 效能測試（Benchmark）
分類：相關延伸｜常見說法：基準測試、效能量測
**它是什麼？** 用固定輸入與環境反覆測一個程式或功能的速度和資源成本。正確性不能因為跑得快就忽略。
**舉個例子：** 同一筆輸入分別跑原版與 DMA 版本。
**什麼時候會用到？** 老師要求證明加速效果時。
**現有觀念文章：** `ncku-performance-benchmark`
**對應優化方案：** `benchmark-correctness::baseline`

### 第 95 百分位延遲（95th percentile）
分類：相關延伸｜常見說法：p95、P95、尾端延遲
**它是什麼？** 若有很多次延遲測量，p95 表示大約 95% 的樣本不超過的數值。它比平均值更能看出少數慢的情況。
**舉個例子：** 平均 10ms，但 p95 可能有 80ms。
**什麼時候會用到？** 關注偶爾卡很久，而非只看平均時。
**現有觀念文章：** `ncku-performance-benchmark`
**對應優化方案：** `perf-tail-latency::option-2-p95`

### 時間複雜度（Time complexity）
分類：相關延伸｜常見說法：O(n)、Big O、時間成本
**它是什麼？** 描述輸入量變大時，運算量大致怎麼變。跟硬體上實際幾毫秒不同，要同時看兩者。
**舉個例子：** 單次掃描 O(n)，完整排序 O(n log n)。
**什麼時候會用到？** 輸入變大後程式突然很慢時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `algorithm-search-batching::option-1-dict-set`

### 空間複雜度（Space complexity）
分類：相關延伸｜常見說法：額外空間、記憶體複雜度
**它是什麼？** 描述演算法使用的額外記憶體隨輸入量成長的程度，不等於程式實際的全部 RAM。
**舉個例子：** 保留一份新陣列通常需要 O(n) 額外空間。
**什麼時候會用到？** 改快取或雙緩衝後 RAM 不夠時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `cpu-memory-locality::contiguous-storage`

### 記憶體錯誤檢查器（Sanitizer）
分類：相關延伸｜常見說法：ASan、UBSan、AddressSanitizer
**它是什麼？** 編譯時加入的工具，可在執行測試時偵測一些越界、未定義行為等問題，不是所有 bug 都能檢出。
**舉個例子：** gcc -fsanitize=address,undefined。
**什麼時候會用到？** C 位元運算、指標或 buffer 修改後怕越界時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `compiler-profile-guided::sanitize-before-speed`

### 未定義行為（Undefined behavior）
分類：相關延伸｜常見說法：UB、undefined、未定義
**它是什麼？** C 語言規格沒有規定該程式情況必須產生什麼結果；編譯器可以作激進優化，所以「這次能跑」不能證明安全。
**舉個例子：** 讀陣列邊界外、非法位移或某些資料競爭。
**什麼時候會用到？** 同樣 C 程式換編譯器就出怪問題時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `c-signed-overflow::option-3-sanitizer`

### Mutex 與 Spinlock 比較（Mutex vs Spinlock）
分類：相關延伸｜常見說法：互斥鎖與自旋鎖、spinlock mutex
**它是什麼？** Mutex 爭用時常有機會阻塞等待；Spinlock 會忙等。兩者都用於互斥，但等待方式和成本不同。
**舉個例子：** 很短的臨界區可先測 spinlock，長時間等待則比較 mutex。
**什麼時候會用到？** CPU 使用率高但工作進度很慢時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `spinlock-critical-section::use-mutex`

### 佇列（Queue）
分類：相關延伸｜常見說法：queue、排隊資料結構
**它是什麼？** 一種儲存待處理工作或資料的結構，先入先出的 queue 很常見。它跟硬體 FIFO 相似，但程式 queue 可能有額外同步或容量規則。
**舉個例子：** producer push 任務，consumer pop 任務。
**什麼時候會用到？** 工作有時湧入、處理端跟不上資料速度時。
**現有觀念文章：** `ncku-pthread-condvar-queue`
**對應優化方案：** `pthread-condition-queue::bounded-ring-buffer`

### Python 全域直譯器鎖（Global Interpreter Lock）
分類：相關延伸｜常見說法：GIL、Python GIL
**它是什麼？** 常見 CPython 執行環境中，GIL 會限制同一個直譯器內多條 thread 同時執行 Python 位元碼的能力。I/O 等待可讓出執行機會。
**舉個例子：** 兩個 CPU 密集的純 Python 函式用 thread 未必多核心加速。
**什麼時候會用到？** 把 ROS 2 的 CPU-heavy callback 改多執行緒卻沒更快時。
**現有觀念文章：** `ncku-ros2-executor`
**對應優化方案：** `python-cpu-process::measure-cpu`

### 程序池（Process pool）
分類：相關延伸｜常見說法：ProcessPoolExecutor、多程序池
**它是什麼？** 建立多個獨立 process 分別運算，可繞開一般 GIL 對單一直譯器的限制，但需要資料序列化與跨程序傳輸。
**舉個例子：** 把可 pickle 的純計算函式交給 ProcessPoolExecutor。
**什麼時候會用到？** 純 Python CPU 計算真的很重時。
**現有觀念文章：** `ros2-ste-process-pool`
**對應優化方案：** `python-cpu-process::process-pool`

### 複製與零拷貝（Copy vs zero-copy）
分類：相關延伸｜常見說法：zero copy、減少複製
**它是什麼？** 少做記憶體複製有時能節省時間，但資料所有權、生命週期和對齊必須明確，不能只把指標直接指過去。
**舉個例子：** 大型 buffer 避免重複複製前先確認沒有並行修改。
**什麼時候會用到？** 大量資料搬來搬去造成效能瓶頸時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `memory-buffer-copy::avoid-extra-copy`

### DMA 與執行緒差異（DMA vs thread）
分類：相關延伸｜常見說法：DMA thread comparison、硬體與軟體搬運
**它是什麼？** Thread 是 CPU 執行的軟體工作；DMA 是獨立硬體發起記憶體或周邊傳輸。Demo 用 thread 模擬 DMA 介面，不能拿它的 CPU 占用當成真 DMA。
**舉個例子：** 模擬 engine 的複製 worker 仍占 CPU；真 DMA 不需要 CPU 逐筆執行。
**什麼時候會用到？** 看完 Demo 2-3 想估計實際硬體效能時。
**現有觀念文章：** `ncku-concurrency-advanced`
**對應優化方案：** `transfer-engine-configuration::overlap-cpu`
